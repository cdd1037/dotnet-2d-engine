# Offline sprite material fragments

Run `python3 scripts/compile-materials.py` from the checkout to compile `tint` and
`desaturate`. It uses the already installed `libshaderc` with no downloads or new
dependencies. To compile a subset, pass names: `python3 scripts/compile-materials.py tint`.
Run `python3 scripts/test-material-builder.py` for the focused builder checks.

Each `.frag` is a complete GLSL fragment, including `#version 450`,
`#extension GL_GOOGLE_include_directive : require`, an ordinary
`#include "sprite-fragment-v1.glsl"`, and `void main()`. The original source is
passed unchanged to shaderc. Shaderc's include callbacks resolve just that fixed
helper, without Python include expansion or a shader DSL. The existing sprite
vertex shader and `scripts/compile_shaders.py` stay the baseline path.

The `sprite-fragment-v1` engine binding convention is:

| Binding | Declaration |
| --- | --- |
| set 2, binding 0 | `sampler2D sprite_texture` |
| input location 0 | `vec2 uv` |
| input location 1 | `vec4 color` |
| output location 0 | `vec4 result` |
| set 3, binding 0 | std140 `MaterialParameters { vec4 first; vec4 second; } material` |

The parameter block is always 32 bytes: eight floats in `first`, then `second`
order. `tint` uses `first` as an RGBA multiplier, so its identity values are
`(1, 1, 1, 1, 0, 0, 0, 0)`. `desaturate` uses `first.x` as desaturation amount
(clamped to 0–1) and `first.y` as RGB brightness; its identity is
`(0, 1, 0, 0, 0, 0, 0, 0)`. Desaturation uses luminance weights
`(0.2126, 0.7152, 0.0722)` and preserves sampled alpha multiplied by vertex alpha.
Other parameter components are reserved and should be zero. Both fragments
produce straight-alpha color for the engine's existing blend state.

The source preflight rejects direct resource/layout declarations and global
stage interfaces outside the helper and requires exactly one fixed `#include`.
Ordinary GLSL macros, conditional preprocessing, `#line` directives, functions,
and calculations remain available; shaderc handles preprocessing normally.
Each source and the helper is limited to 64 KiB; the include callback rejects
depth greater than 8 and every other include name. The textual preflight does
not analyze macro expansion or evaluate conditional compilation, so authors must
preserve the fixed interface even when using preprocessing. This restricted
binding convention is not semantic SPIR-V reflection, binary-layout
verification, or a sandbox. Material source and compiled shaders must remain
trusted authored assets.

The builder targets Vulkan 1.0 / SPIR-V 1.0 and writes these sibling assets:

- `assets/materials/<name>.frag.spv`: generated binary, ignored by Git
- `assets/materials/<name>.material.json`: deterministic tracked manifest with
  `version`, `profile`, `fragment`, `sha256`, and `parameterBytes`

`fragment` names its sibling SPIR-V file. `sha256` records the exact generated
bytes, and `parameterBytes` is 32. Manifest metadata and hashes do not prove a
binary's shader interface. Compiler upgrades can change the generated bytes;
rebuild and commit the resulting manifests together with authored source changes.

All requested materials compile before any output is modified. Each compiled
blob must also match the runtime's header contract: 20–262144 bytes, a whole
number of 4-byte words, SPIR-V 1.0 magic/version, schema 0, and an ID bound from
1 through `0x3fffff`. These checks do not validate instructions or shader layout.
A compilation, preflight, or compiled-header error reports the source and leaves
every prior artifact untouched.
Successful outputs are staged in the destination directory, replaced atomically
per file, and manifests are published after all binaries. This is not an atomic
multi-file transaction in the face of an I/O failure or process interruption;
rerun the builder if either occurs. `--source-dir` and `--output-dir` allow
isolated authoring/test locations; the include always uses this checkout's fixed
engine helper.
